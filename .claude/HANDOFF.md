### 한글 IME — 다시 건드릴 때 주의

검색칸에서 한글이 자모로 풀리던 문제를 **세 번** 고쳤다. 원인은 하나였다 —
`render()` 가 `innerHTML` 을 통째로 갈면 진행 중인 IME 조합이 깨진다.

- 조합 중(`compositionstart`~`end`)에는 **입력칸을 다시 그리지 않는다.**
- 특히 **음절이 확정되는 순간**이 함정이다. `compositionend` 와 다음
  `compositionstart` 가 붙어서 오는데, 그 사이에 그리면 방금 시작된 조합이 깨진다.
  그래서 검색 중에는 `render()` 를 아예 부르지 않고 결과 목록만 갈아 끼운다.
- `oncompositionstart` / `oncompositionend` 는 **HTML 인라인 속성이 아니다**
  (`onclick`·`oninput` 과 달리 표준 목록에 없어 브라우저가 무시한다). document 위임으로 건다.
- ④ 원청과 ⑤ 협력사가 **같은 칸을 쓴다**(`qCfg`/`coPicker`/`coResults`). 두 벌로 두면
  한쪽만 고치는 일이 생긴다 — IME 를 세 번 고치는 동안 ⑤ 는 손도 안 댄 상태였다.
- 엔터는 `e.isComposing` 으로 걸러야 한다. 조합 확정 엔터와 결과 선택 엔터는 다른 동작이다.
- **검증할 때 `compositionend` 를 맨 끝에 한 번만 보내면 안 된다.** 실제 키보드는
  음절마다 end/start 를 반복한다. 그 경로를 안 밟으면 버그가 통과한다(두 번 놓쳤다).

`render()` 는 입력칸의 포커스와 커서를 잃는다. 다시 그리기 전 위치를 기억했다가
`restoreFocus()` 로 되돌린다(부모에서 몇 번째 자식인가로 자리를 잡는다).

### 막혔던 CSV 파일명 문제 — 풀 필요가 없었다

이전 세션은 `statisticsDown.json?f=…&s=…` 의 `s=` 규칙을 찾으려 했다. 그 방향은 막다른 길이다.
`일반현황`은 화면에 하드코딩된 특수 케이스라 되는 것이었고, 항목별 파일명은 서버가 쥐고 있다.

**화면이 실제로 쓰는 JSON 이 따로 있다.** `/resources/vue/app.js` 에서 찾았다.

```
GET /statisticsSearch/findSingleItemSearchList.json
    ?pageNo=1&countPerPage=100&reportFormNo=<rf>&itemNo=<ino>
```

- `treeCode` = `"<reportFormNo>-<itemNo>"` (findItemTreeList.json 의 각 잎 노드)
- 응답: `{status:"success", data:{result:[...], page:{totalPage,...}}}`
- 한 행 = 한 기관 × 6개 연도(`yy5`..`yy0`) + `apbaId/apbaNa/apbaTypeNm/jidtDptmNa/itmsUnitNm`
- `countPerPage` 상한은 **100**. 355곳이면 4쪽을 돈다.
- CSV 파싱도, 인코딩 씨름도, 파일명 추측도 없다.

관련 다운로드 엔드포인트(`downExcelSingleItem.json`)도 확인했지만 쓸 이유가 없다.

### 반드시 알고 있어야 할 함정 세 가지

1. **연도 기준이 섞여 있다.** 알리오 각주 그대로: `yy5`..`yy1` = 결산, `yy0`(=당해년도) = **예산편성** 기준.
   실제로 한전은 결산 96,381천원 → 예산 87,389천원으로 뚝 떨어진다. 섞어 평균 내면 안 된다.
   화면의 기본 비교는 결산 마지막 해만 쓴다(`psLast`).
   `GB_alioYear` 는 화면에서 정규식으로 읽는다 — 하드코딩하면 해가 바뀔 때 조용히 틀린다.

2. **단위를 짐작하면 틀린다.** `평균근속연수`는 '년'이 아니라 **월**로 온다(`itmsUnit=5`).
   그래서 수집기는 우리가 적어 둔 단위 대신 **응답의 `itmsUnitNm` 을 따르고**, 다르면 diag 에 WARN 을 남긴다.

3. **중간 노드는 값이 안 온다.** `20202-GI020102`(일반정규직>현원)처럼 자식이 있는 노드는 0건이다.
   잎인 `20202-GI02010201`(현원>계)을 써야 한다.

그리고 **0 이 '없음'인 항목이 있다.** 신입사원 초임 0은 0원이 아니라 그 해 신규채용이 없었다는 뜻이다
(대한석탄공사·한국통계정보원). 중위값과 등수에서 빼고, 근속 모형도 계산하지 않는다.

### 설계 결정 (지킨 것)

- **기능별 11개 분류** — 알리오 공식 분류(공기업/준정부/기타)는 법적 지위라 임금 비교에 못 쓴다.
  기관명 규칙을 먼저 보고, 안 걸리면 주무부처로 넘긴다. 기관명이 부처보다 안정적이다
  (2026년 개편으로 기후에너지환경부·산업통상부·재정경제부·지식재산처 등으로 이름이 다 바뀌었다).
  **연구·학술 규칙이 맨 앞**이다 — 에너지경제연구원의 노동시장은 발전소가 아니라 다른 출연연이다.
  분류 근거를 기관마다 `why` 로 실어 화면에 표시한다. 우리가 만든 분류라고 못 박아 뒀다.
  conects 사이트는 **분류 체계만 참고**했고 데이터 출처로 쓰지 않았다.
- **④ 로직을 쓰지 않았다** — 공공기관은 이익이 없어 지불능력 계산이 성립하지 않는다.
  총인건비 인상률은 기재부 지침 소관이고 공개 API 가 없어 **이용자 직접 입력**이다.
  대신 355곳 평균보수의 전년비 중위값을 같이 보여준다 — 지침 수치가 아니라 **실제 결과**라
  "지침대로 올렸는데 왜 체감이 다른가"를 물을 수 있다.
- **성별 격차를 근속으로 분해한다** — DART 에 없는 축이라 여기서만 가능하다.
  `보수 = 신입 초임 + (근속 1년당 증가분 × 근속)` 직선을 그 기관 공시값만으로 세운다.
  초임을 절편으로 쓰는 게 핵심 — 비례로 두면 근속 0년의 보수가 0원이 되어 격차가 부풀려진다.
  직종 구성이 갈리는 기관(병원 등)엔 안 맞는다고 화면에 크게 적어 뒀다. 결론이 아니라 질문의 출발점이다.
- **실패하면 조용히 넘기고 로그를 남긴다** — 항목별로 독립 실패하고, 전부 실패할 때만 기존 파일을 보존한다.
  원인은 출력 JSON 의 `diag` 배열에 남는다. 트리에서 코드가 사라지면 먼저 걸린다.

### 주기가 갈렸다

```
매일 KST 10:00    물가·임금·GNI·공공부문        (몇 분)
일요일 KST 11:00   + 회사 재무 (DART 1,883곳)   (3시간+)
수동 실행          companies 입력으로 회사 포함 여부를 고른다
```

회사 재무는 실측 3시간이다. 회사 한 곳당 DART 를 최대 7번 물어야 하고(직원현황·손익을
최근 3개 사업연도까지 + 업종) 1,883곳이면 13,000회다. 그런데 사업보고서는 연 1회
공시다. 매일 돌 이유가 없어 주 1회로 뺐다.

8곳에서 1,883곳으로 늘린 것이 수동 작업이었고 그 규모로 Actions 가 돌아 본 적이
없어 이제야 드러났다. 그전 실행이 5~6분에 끝난 기록은 8곳 시절의 것이다.

  자동으로 넘길 수 있다. 지금은 이용자가 보고 옮겨 적어야 한다.
- **지방공공기관** — 클린아이(cleaneye.go.kr)에 별도 공시. ⑩ 에 없다. 붙일지는 미정.
- ⑪ 에 경찰·소방·교원·군인 봉급표 붙이기 — `public_servant_pay.json` 에 원본이 이미 있다.
  일반직 외에는 구조화만 안 해 둔 상태다.
- 알리오에서 아직 안 쓴 항목: 소속외인력의 파견/용역/사내하도급 **내역별**,
  정규직 전환 실적·비율, 평균임금 비율(성별), 자회사, 신규채용 중 여성·장애인·지역인재·고졸.

**남은 판단 하나**

- guide '왜 만들었나' 4문단의 "격차는 삶의 질을 떨어뜨린다" 는 **가치 판단**이다.
  도구의 목적 선언으로 두었고 바로 아래 '중립 원칙' 과는 층이 달라 충돌하지 않는다.
  톤을 낮추길 원하면 그 문단만 조정하면 된다.

## ⑪ 공무원 — 다시 건드릴 때

`public_servant.py` → `docs/public_servant.json`(34KB) + `public_servant_pay.json`(169KB).
둘 다 키가 필요 없다.

- **봉급표** — 인사혁신처 `bizSalary/{연도}/`. HTML 표로 그대로 있다. 연도별 URL 규칙이 같다.
  표 구조가 해마다 바뀐다(2023년 이전 20종 → 이후 11종). 그래서 **해석하지 않고**
  머리행·데이터행을 그대로 담고 일반직만 계급×호봉으로 구조화한다.
- **민간 대비 보수수준** — 지표누리 OpenAPI 는 승인 심사를 요구하지만,
  화면이 쓰는 주소는 키가 필요 없다.
  `showStblGams3.do?stts_cd=102101&idx_cd=1021&freq=Y&period=N`

**본봉과 총액을 섞지 말 것.** 봉급표는 본봉뿐이고 알리오 신입 초임은 수당·성과급을 더한
합계다. 그냥 나누면 9급 초임이 공공기관의 64.6% 로 나와 교섭에서 그대로 반박당한다
(수당 90만원을 넣으면 91.8%). 그래서 **수당을 넣기 전에는 비교를 보여주지 않는다.**
접근율도 수당·연금부담금 포함 총보수 기준이라 봉급표 숫자와 곱하거나 빼면 안 된다.

공무원노조법 제10조 — 법령·조례·예산으로 정해지는 내용은 단협 효력이 없다.
⑪ 은 교섭 문안이 아니라 공무원보수위원회 → 기재부 예산 라인을 향한 근거다.

## KOSIS — 다시 건드릴 때

오류 20(필수요청변수값 누락)에 오래 막혀 있었다. 원인은 두 가지였다.

- **엔드포인트.** `statisticsData.do` 는 무엇을 넣어도 오류 20 이다.
  화면의 [OpenAPI] 가 만들어 주는 것과 같은 `Param/statisticsParameterData.do` 를 쓰고,
  `itmId` 와 `objL1` 을 반드시 넣는다.
- **통계표를 이름으로 찾은 것.** '가구원수' 로 검색하면 가계동향조사의
  '가구원수별 가구당 월평균 가계수지' 가 먼저 잡힌다. 가구원수를 분류 기준으로 쓸 뿐
  평균 가구원수가 아니다. **통계표를 지정할 것.**

```
101 / DT_1JC1501  인구총조사 가구형태별 가구 및 가구원
objL1=00(전국)  itmId=T1100(총가구)+T1200(총가구원)  prdSe=Y  jsonVD=Y
```

KOSIS 에 '평균 가구원수' 항목은 없다 — 총가구원 ÷ 총가구로 만든다.
`objL1=ALL` 은 시군구까지 와서 4만 셀 제한(오류 31)에 걸린다.

수집만 하고 화면이 안 쓰던 문제도 있었다. `household_size` 가 JSON 에 있어도 어디서도
읽지 않아 보이지 않았다. **수집기를 고쳤으면 화면이 그 값을 쓰는지 반드시 확인할 것.**
