# 판례 찾기 — 설계 (2026-11-05)

## 맥락 (Context)

- 사용자 요청: 현장 상황을 입력하면 관련 노동·노무 판례를 찾아 주는 기능. **챗봇보다 비용이 들지 않을 것.**
- 사이트는 GitHub Pages 정적 사이트(`master` 의 `docs/`)이고 서버가 없다. 사이트 검색(`site.js`)은 브라우저 안에서만 돈다.
- 2026-09-29 기록 "챗봇은 만들지 않음"은 뒤집지 않는다. 이번 기능은 대화·답변 생성이 없는 **검색**이다.
- about.html 약속: 입력값은 서버로 가지 않는다. 이 약속을 유지한다.
- 법제처 공용 계정 `OC=test` 가 막혔다. `law_watch.json` 은 2026-10-28 뒤로 갱신이 없고(건강 검진 이슈 #2), `public_servant.py` 의 연혁 조회도 같은 응답으로 실패한다.
- 사용자의 키가 `../easylaw/functions/.env` 의 `LAW_API_OC` 에 있다. 2026-11-05 이 PC에서 작동을 확인했다. GitHub Actions 에서 작동하는지는 아직 모른다.

## 문제 (Problem)

1. 현장의 말("내일부터 나오지 말래요")과 판례의 말("해고", "근로기준법 제23조")이 달라 낱말 검색으로는 찾기 어렵다.
2. 판례 약 5천 건을 정적 사이트에서 가볍게 검색해야 한다.
3. 찾은 판례가 내 사건의 결론처럼 읽히면 안 된다. 사이트는 "노무·법률 자문이 아닙니다"라고 밝히고 있다.
4. 법제처 응답의 `판례상세링크`에 키가 들어 있다. 공개 저장소에 그대로 저장하면 키가 유출된다.

## 접근 방식 (Approaches)

| 방식 | 내용 | 결과 |
|---|---|---|
| ① 판례 모음 + 브라우저 검색 | 판례를 미리 모아 공개 파일로 두고, 입력은 브라우저 안에서 대조 | **사용자가 선택.** 비용 0원, 입력값 약속 유지, 사이트 안에서 판례 열람 |
| ② 쟁점 안내 + 외부 연결 | 쟁점·조문을 보여 주고 법제처 검색으로 연결 | 키가 필요 없지만 판례는 외부에서 찾아야 함 |
| 챗봇 / 브라우저 내 AI 모델 | 대화형 답변, 또는 의미 기반 검색 | 비용·정확성 문제(챗봇), 대용량 내려받기(모델) 때문에 제외 |

## 목표 · 비목표 · 하지 말 것

- **목표:** 상황 입력 → 쟁점 확인 → 비슷한 판례 목록 → 요지 열람 → 원문 링크.
- **1단계 범위:** 측정표의 노동 법률 판례(약 5천 건, 표기 변형으로 늘 수 있음).
- **비목표(이번 제외, 내 판단):** 산재보험법 판례, 노동위원회 결정문. 규모가 3~9배라 1단계가 안정된 뒤 따로 다룬다. 화면에 "산재·노동위 결정은 아직 없음"이라고 적는다.
- **하지 말 것:** 승소 가능성·유불리 판단, AI 요약, 입력값 전송·저장, 입력값을 주소(URL)에 넣기. 근로자 승소·패소를 가리지 않고 보여 준다.

## 해결 (Solution)

### 1. 키와 고장 수리 (먼저)

- `LAW_OC` 를 GitHub Secret 으로 등록한다. 사용자 지시로 구현자가 등록한다(값이 화면·로그·대화에 나오지 않게). 등록이 끝나야 Actions 시험을 할 수 있다.
- `law_watch.py`, `public_servant.py` 의 `OC=test` 를 환경변수로 바꾸고 `data.yml` 에 전달한다. 키가 없으면 `RuntimeError` 로 멈춘다(dev fallback 금지).
- 법제처가 `사용자 정보 검증에 실패` 를 주면 "현행 항목 없음"으로 뭉개지 말고 실패로 드러낸다. 실패해도 기존 파일은 보존한다.
- 수동 실행으로 Actions 에서 키가 통하는지 확인한다. **여기서 갈린다.**
  - 통하면 모든 수집을 Actions 에서 한다.
  - 막히면(IP 등록 필요) 사용자가 open.law.go.kr 의 API 관리 화면에서 풀 수 있는지 먼저 본다. 안 풀리면 사용자 PC를 정식 경로로 삼는다: Windows 작업 스케줄러로 법령 감시는 매일, 판례는 주 1회 돌려 `pull --rebase` 후 push 한다. 꺼져 있어 놓친 실행은 다음 켤 때 돌린다. health_check 신선도 기준은 판례 15일, 법령 감시 7일로 늘리고 `data.yml` 의 해당 단계는 지운다.

### 2. 수집기 `prec_watch.py`

- 표준 라이브러리만 쓴다. `LAW_OC` 환경변수. 요청 간격 1.2초 이상.
- 법령별 JO 조회(표기 변형 포함) → 판례일련번호로 합치기(중복 제거) → 상세 조회.
- **저장 항목을 지정한다(allowlist):** 판례일련번호, 사건번호, 사건명, 법원명, 선고일자, 판결유형, 판시사항, 판결요지, 참조조문, 어떤 JO 로 찾았는지. `판례상세링크` 와 전문은 저장하지 않는다. 쓰기 전에 산출물에 키 문자열이 없음을 assert 한다.
- HTML 태그(`<br/>` 등)를 제거해 평문으로 저장한다.
- 첫 수집은 이 PC에서 백그라운드로(약 2시간) 돌리고 이어 받을 수 있게 한다. 이후에는 `sort=ddes` 로 새 판례만 받는다.
- 산출물에 `generated_at`, 총 건수를 넣는다. 실패 시 기존 파일을 보존한다.
- `data.yml` 에 일요일 실행으로 추가하고(`|| echo` 패턴), `health_check.py` 의 FRESH 에 8일 기준으로 등록한다.

### 3. 데이터 파일 (`docs/prec/`)

- `index.json`: 검색용. 첫 검색 때 한 번 받는다. **gzip 후 2MB 이하.**
- `d/NN.json`: 요지 등 상세 조각. 펼칠 때만 해당 조각을 받는다. 일련번호로 조각을 정한다.
- `terms.json`: 용어 사전.
- 저장소 부담을 줄이려고 내용이 그대로면 다시 쓰지 않는다(바뀐 조각만 커밋).

### 4. 용어 사전 (이 기능의 핵심)

- 쟁점 30개 안팎: 쟁점 이름, 현장 표현 목록, 법률 용어, 관련 조문, 관련 법.
- 예: `부당해고` ← "나오지 말래", "짤렸", "그만두라" / 용어 해고·정당한 이유 / 근로기준법 제23조.
- 조문 번호는 법제처 원문과 대조한다. 사실 자료이므로 독립 검토(critic)를 거친 뒤 원자료로 다시 대조해 반영한다.
- 쟁점의 첫 묶음: 해고·징계·수습·계약 만료·임금 체불·통상임금·퇴직금·휴일/연장수당·근로자성·위장도급/파견·원청 사용자성·단체교섭 거부·부당노동행위·쟁의행위 손해배상·차별·직장 내 괴롭힘·취업규칙 변경.

- 입력에 쟁점이 하나도 안 잡히면 쟁점 목록에서 고르게 한다. 입력 낱말 검색으로도 찾는다.

- 판결요지가 빈 판례는 판시사항을 보여 주고 원문으로 안내한다.
- 외부 데이터는 `textContent` 로만 넣는다(`innerHTML` 금지). 입력값은 `localStorage` 에도 저장하지 않는다.
- 원문 링크는 키 없는 공개 주소 `https://www.law.go.kr/LSW/precInfoP.do?precSeq=<판례일련번호>` 를 쓴다(2026-11-05 표본 1건 확인).
- 화면과 about.html 에 **출처: 법제처 국가법령정보센터** 를 적는다. 법제처 안내는 출처 표시 누락·오기를 저작권법 위반으로 경고한다. 공유서비스 API 는 공공누리 제1유형(출처 표시)으로 표기되어 있어 요지의 공개 저장을 허용으로 판단했다. 다만 이 표기는 data.go.kr 항목 기준이고, 판례 자료에 대한 별도 조건 문구는 확인하지 못했다. 제공이 중단되거나 조건이 다르면 요지를 빼고 제목·링크만 남기도록 데이터와 화면을 나눠 둔다.

## 판결문 본문 표지 (2026-11-05 추가)

- **왜**: 색인은 판시사항과 요지 앞 300자만 담는다. 그래서 '직장 내 괴롭힘'처럼 판결문 본문에만 나오는 표현은 색인에서 0건이다. 법제처 본문 검색(search=2)은 낱말을 쪼개 찾아 믿을 수 없다(표본 0/4).
- **무엇을**: `terms.json` 의 `body` 에 적은 몇몇 표현만, 상세 조회 때 함께 받는 판결문 원문(`판례내용`)에서 수집기가 직접 확인해 판례에 `tags` 로 붙인다. 원문 자체는 어떤 산출물에도 넣지 않는다(2MB 제한, allowlist 원칙). 표현 목록이 바뀌면(`tv` 불일치) 다음 실행에서 다시 확인하고, 다시 확인이 실패해도 기존 상세는 그대로 두었다가 다음 실행 때 재시도한다. 검색은 표지만 있는 판례를 요지 일치 판례 뒤에 둔다.
- **한계**: 참조조문 없는 하급심은 수집 대상 밖이라 표지도 없다. 표현은 공백만 무시한 부분 문자열 일치라 부정문·반대 취지의 문장도 잡힌다.
